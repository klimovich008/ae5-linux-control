# AE-5 audio-safety preflight

Execute these steps in order and report each result. Abort the planned
audio work if any step fails.

## 1. Put the output into the fail-safe state

```sh
wpctl set-mute @DEFAULT_AUDIO_SINK@ 1
wpctl set-volume @DEFAULT_AUDIO_SINK@ 20%
ae5ctl set-playback-switch Master off
ae5ctl set-playback-switch Front off
```

## 2. Confirm every AE-5 playback PCM is closed

```sh
for status in /proc/asound/card*/pcm*p/sub*/status; do
    printf '%s: ' "$status"; sed -n '1p' "$status"
done
```

All must read `closed`. If any is open, find and stop the client first.

## 3. Confirm gain and route state

- Headphone gain must be **Low** (`ae5ctl status`). Never High for tests.
- Route must match the intended test (`ae5ctl route-status`).
- Run the project's own gate: `cargo run -- route-status` or the installed
  `ae5ctl route-status`, and the relevant `playback-preflight` from
  `scripts/` immediately before playing a fixture.

## 4. Rules during the test

- Only fixtures generated by `scripts/audio-parity.sh` (it rejects peaks
  above the project ceiling). Never real music for unattended tests.
- Keep every project-controlled test at or below 20%; first playback after
  any change happens with headphones OFF the user's head.
- Emergency mute: `ae5ctl set-playback-switch Master off`.

## 5. After the test

Return to: sink muted at the user's usual level, both hardware switches per
their chosen state, all PCMs closed. Re-run step 2 and report the final state.
